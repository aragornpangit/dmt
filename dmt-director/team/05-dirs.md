# 目录与产物边界

1. 产物位置由任务或项目约定；只写明确分配的路径，不擅自创建平行目录。
2. 需求、调研、实现、评审和运行时消息可有不同负责人，但同一产物只设一个权威写者。
3. 实现者和评审者默认通过回报交付证据；需要落盘时写入任务指定位置。
4. 临时文件、运行时通道和本地凭证不得混入正式交付物或提交。

没有既有约定时，可采用以下可选布局：

```text
docs/pd/prd/       产品需求
docs/pd/spec/      技术规格
docs/dev/tickets/  开发工单
docs/analyst/      调研报告与证据索引
docs/handoff/      交接与验收结论
inbox/<role>/      启用收件箱适配器后的运行时消息
```

`dmt-director/scripts/init-project.sh <项目根>` 用于显式建立 DMT 默认目录，不是角色加载步骤。通用项目检查不要求这些目录存在。
