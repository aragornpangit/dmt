# 命名约定

项目已有命名规范优先；没有时再采用本约定。

- 文件名应能识别产物类型、主题和版本，使用简短 slug，避免无意义编号堆砌。
- 需求、规格、工单和测试使用稳定标识互相引用；重命名时保留可追溯关系。
- 小修可原地更新；实质修订按项目版本策略处理，并标明替代关系。
- 历史文件不为迎合新规则批量改名。
- 运行时消息与正式产物分开命名，消息序号不得重用。

## SPEC 与工单的编号（`{spec-seq}` 与 `{ticket-seq}`）

- SPEC 用纯号 `{spec-seq}`（一条需求的「链」号）。工单序号 `{ticket-seq}` 不是独立全局序列，而是两级复合值 **`{spec-seq}.{NN}`**：`.` 是层级分隔符（非小数点、非版本号），前半是所属 SPEC 号，后半是该 SPEC 下的第 NN 张工单。例 `089.02` ＝ SPEC-089 的第 2 张票。
- SPEC：`{seq}-spec-{slug}-{ts}--v{N}.md`。票：`{seq}.{NN}-ticket-{slug}-{ts}--v{N}.md`，票面「票号」写 `{seq}.{NN}`；`.` 只在编号段出现一次（扩展名 `.md` 除外），slug／时间戳仍用 `-`。
- `NN` 从 `01` 起、**只在同一 spec-seq 内自增**，不同 SPEC 各自从 01 计数；作废票的 NN 不回收、不重用。首票也带 NN（无「首票例外」）；某 SPEC 的历史首票若无 NN，视作 `.01`，其后新票从 `.02` 起。
- 纯号只归 SPEC：工单不再占用纯 `{spec-seq}`，避免票抢占后续 SPEC 的号；票面须显式写「对应 SPEC：`{seq}`」建立追溯，不依赖同号隐式关联。
- 无父 SPEC 的工单（门治理、取证、勘误、审计修复等）仍用全局 `{seq}-ticket-{slug}`，**不带 `.`**、与 `{spec}.{NN}` 不同空间；取号照旧（三类目录实查、DM 唯一关口）。
- 只向前生效：历史件保留原名（见上「历史文件不为迎合新规则批量改名」）。历史子票的 `-NN` 形态（`089-02`／`103-01`／`056-02` 等）**不是**新 `.NN` 形态的等价写法，禁止互相换算、去重或合并；分支名／工具目录／证据目录里的裸号与 `-NN` 引用点保持原样，票面登记映射即可。

可选 DMT 形式为 `<id>-<type>-<slug>-<timestamp>--v<N>.md`；id 位数、时间精度和版本形式均可由项目覆盖。收件箱命名见 [`../ops/comms.md`](../ops/comms.md)。
