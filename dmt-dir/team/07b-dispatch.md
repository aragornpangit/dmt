# 可选：派发模板

按任务裁剪字段，不为简单工作堆砌流程。

```text
角色与技能：<能力或技能路径>
单元：<一句话目标>
输入：<需求、代码、资料及位置>
边界：<允许与禁止修改的范围>
产物：<位置与格式>
判据：<逐项可测>
验证：<命令、来源或证据要求>
回报：<结果、证据、未决项；只报派发者>
约束：<时间、资源、安全或平台要求，按需>
```

启用第三方技能适配器时，「角色与技能」行按 [`../ops/optional-skills.md`](../ops/optional-skills.md) 逐项写出本单元所需技能/MCP；未安装或不可用标 `[SKILL_UNAVAILABLE]` 并回报派发者，不静默跳过。

独立评审额外写明（由 `dmt-dl` 派未参与实现的临时子代理承担，不设专用技能）：

```text
你未参与本单元实现，只依据需求、变更和证据逐项验收。
不得修改实现或判据；无证据不得判 PASS。
```

## 平台适配

- 优先使用平台原生命名子代理、技能注入和完成通知。
- 无法命名子代理时，可在 prompt 中明确角色并给出技能文件路径。
- pi 使用已安装的 `pi-agents/` 角色定义；未安装时用 `delegate` + 技能绝对路径回退，二者都不是全局唯一方式。
- 平台不支持子代理时报告能力缺口，在当前上下文完成可独立处理的部分，不伪造派发。
- 具体机制见 [`../harness/README.md`](../harness/README.md)，仅在实际使用时读取。
